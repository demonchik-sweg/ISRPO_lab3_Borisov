## 1. Архитектура VS Code в контексте разработки плагинов

### 1.1. Общая модель VS Code

VS Code — это приложение на базе Electron, состоящее из нескольких процессов:

- **Renderer** — интерфейс: окна, вкладки, редактор, панели.
- **Main** — управляющий процесс: работа с файлами, окнами ОС.
- **Extension Host** — отдельный процесс, в котором выполняются все расширения.

Расширения изолированы от UI. Они не могут напрямую менять интерфейс — только через официальный API (`vscode.*`).

### 1.2. Схема подключения расширения

```
┌─────────────────────────────────────────────────┐
│              VS Code (Electron)                 │
│                                                 │
│  ┌──────────────┐        ┌───────────────────┐ │
│  │  Renderer    │◄──────►│   Extension Host  │ │
│  │  (UI)        │  IPC   │                   │ │
│  │              │        │  ┌─────────────┐  │ │
│  │  Editor      │        │  │ Memory Size │  │ │
│  │  Sidebar     │        │  │ (плагин)    │  │ │
│  │  StatusBar   │        │  └─────────────┘  │ │
│  └──────────────┘        │                   │ │
│                          │  ┌─────────────┐  │ │
│                          │  │  Copilot    │  │ │
│                          │  ├─────────────┤  │ │
│                          │  │  C/C++ Ext  │  │ │
│                          │  ├─────────────┤  │ │
│                          │  │  ...        │  │ │
│                          │  └─────────────┘  │ │
│                          └───────────────────┘ │
└─────────────────────────────────────────────────┘
```

### 1.3. Точки расширения

VS Code предоставляет точки расширения (extension points), к которым подключается плагин:

| Точка | Что даёт |
|---|---|
| `commands` | Добавить команду в палитру |
| `keybindings` | Привязать горячую клавишу |
| `languages` | Добавить поддержку языка |
| `grammars` | Подсветка синтаксиса |
| `configuration` | Свои настройки |
| `snippets` | Шаблоны кода |
| `viewsContainers` | Своя панель в сайдбаре |

Плагин декларирует точки расширения в `package.json`, а реализует их в `extension.ts`.

### 1.4. Activation Events — ленивая загрузка

VS Code не загружает все плагины сразу. Каждый плагин декларирует события активации:

```json
"activationEvents": ["onCommand:memorysize.run"]
```

Читается как: «загружай этот плагин, только когда пользователь впервые вызовет команду `memorysize.run`».

Преимущества:
- Быстрый старт VS Code.
- Экономия оперативной памяти.

### 1.5. Точка входа

Каждое расширение экспортирует две функции:

```typescript
export function activate(context: vscode.ExtensionContext) { ... }
export function deactivate() { ... }
```

- `activate` — вызывается при загрузке расширения. Регистрирует команды, обработчики, UI.
- `deactivate` — вызывается при выгрузке. Освобождает ресурсы.

Параметр `context` даёт доступ к API VS Code и хранит подписки.

### 1.6. Подписки (Disposables)

Каждый ресурс (команда, обработчик, UI-элемент) возвращает объект `Disposable`. Их нужно складывать в `context.subscriptions`:

```typescript
context.subscriptions.push(
    vscode.commands.registerCommand('...', () => { ... })
);
```

При выгрузке VS Code автоматически вызовет `dispose()` у всех подписок — защита от утечек памяти.

## 2. Архитектура плагина Memory Size

### 2.1. Общая блок-схема

```
Пользователь → Ctrl+Alt+M
    ↓
Команда memorysize.run
    ↓
Получить текст активного .cpp файла
    ↓
parseDeclarations(text)
    ├── parsestaticarrayDeclarations
    ├── parseVectors
    ├── parsePairs
    └── parseAnnotations
    ↓
Сбор символов (n, m, ...) → Set<string>
    ↓
showInputBox для каждого символа → Map<string, number>
    ↓
computeTotalMemory(decls, values) → number (байты)
    ↓
statusBar.text = "Память: X.XX МБ"
```

### 2.2. Структуры данных

| Структура | Назначение |
|---|---|
| `Map<string, number> typesize` | Размеры базовых типов C++ |
| `Map<string, number> ALGORITHMS` | Накладные расходы алгоритмов |
| `interface Declaration` | Описание одного объявления |
| `Set<string>` | Уникальные символы из размеров |
| `Map<string, number>` | Значения, введённые пользователем |
| `Declaration[]` | Все найденные объявления |

### 2.3. Модули (функции)

| Функция | Ответственность |
|---|---|
| `activate` | Регистрация команды, создание статус-бара |
| `parseDeclarations` | Оркестратор — вызывает все парсеры |
| `parsestaticarrayDeclarations` | Поиск массивов через regex |
| `parseVectors` | Поиск `vector<...>` через стек скобок |
| `parsePairs` | Поиск `pair<...>` |
| `parseAnnotations` | Разбор `///ALGO ...` |
| `extractTemplateArg` | Извлечение содержимого `<>` |
| `getTypeSize` | Рекурсивный подсчёт размера типа |
| `parseVectorArgs` | Разбор аргументов конструктора вектора |
| `splitTopLevel` | Деление по запятым с учётом вложенности |
| `computeTotalMemory` | Суммирование объёмов |
| `fmt` | Форматирование байтов в КБ/МБ |

### 2.4. Алгоритм работы

1. **Активация** — пользователь нажимает `Ctrl+Alt+M`.
2. **Проверка** — активен ли файл `.cpp` / `.c`.
3. **Чтение** — получить текст через `editor.document.getText()`.
4. **Парсинг** — вызвать 4 парсера, объединить результаты.
5. **Сбор символов** — регуляркой найти все идентификаторы в размерах.
6. **Диалог** — для каждого символа запросить значение.
7. **Подстановка** — заменить символы на числа в формулах.
8. **Вычисление** — перемножить размеры и умножить на `sizeof`.
9. **Вывод** — записать результат в `statusBar.text`.

### 2.5. Использование API VS Code

| API | Назначение |
|---|---|
| `vscode.window.activeTextEditor` | Получить активный редактор |
| `editor.document.getText()` | Прочитать содержимое |
| `editor.document.languageId` | Проверить язык файла |
| `vscode.window.showInputBox` | Диалог ввода |
| `vscode.window.createStatusBarItem` | Создать надпись внизу |
| `vscode.commands.registerCommand` | Зарегистрировать команду |
| `context.subscriptions.push` | Управление подписками |

### 3.2. Основные технические решения

- **Регулярные выражения** — для простых случаев (массивы, пары).
- **Стековый парсер** — для вложенных шаблонов `vector<vector<pair<int,int>>>`.
- **Рекурсия** — для подсчёта размеров составных типов.
- **`eval`** — для вычисления выражений после подстановки символов.
- **JSDoc** — комментарии над каждой функцией.

### 3.3. Пример работы

**Входной файл:**

```cpp
#include <bits/stdc++.h>
using namespace std;

///DIJKSTRA m 2 long long, int

int main() {
    int n, m;
    cin >> n >> m;

    vector<vector<pair<int,int>>> g(n);
    vector<long long> dist(n);
    priority_queue<pair<long long,int>> pq;
}
```

**Ввод пользователя:**
- `n = 100000`
- `m = 200000`

**Результат в статус-баре:**

```
Память: 6.25 МБ
```

**Разбор:**

| Объявление | Формула | Размер |
|---|---|---|
| `vector<vector<pair<int,int>>> g(100000)` | `100000 × 24` | 2.4 МБ |
| `vector<long long> dist(100000)` | `100000 × 8` | 800 КБ |
| `DIJKSTRA` (аннотация) | `200000 × 12 + 24` | 2.4 МБ |
| **Итого** | | **~6.25 МБ** |

## 4. Ограничения

### 4.1. Что не учитывается

- **Padding (выравнивание)** — `pair<int, long long>` реально 16 байт, плагин считает 12.
- **Динамические структуры без аннотации** — `set`, `map`, `deque` не считаются.
- **Кастомные типы** — только через описание полей в аннотации.
- **`new` / `malloc`** — ручное выделение памяти не отслеживается.
- **Стек рекурсии** — рекурсивные вызовы не учитываются.
- **Изменения размера** — `push_back`, `resize`, `reserve` не отслеживаются.

### 4.2. Принципиальные ограничения

- **Точная оценка памяти алгоритмов невозможна** — размер `priority_queue` в Дейкстре зависит от данных и порядка обхода. Аннотация даёт верхнюю оценку через указанный размер.
- **Общая задача оценки памяти неразрешима** — следствие теоремы Райса: нельзя алгоритмически определить нетривиальные свойства программы по её тексту.
